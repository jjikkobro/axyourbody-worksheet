# AX YOUR BODY 디자인 기준

운동 계획을 읽고, 필요한 내용을 바꾸고, 실제로 한 운동을 남기는 도구다. 따뜻한 배경과 절제된 초록색 위에 **현재 상태 → 다음 행동 → 변경 영향 → 저장 결과**를 순서대로 보여 준다. 기록은 오늘의 행동을 결정하는 참고 자료로 배치한다.

이 문서는 [현재 HTML 프로토타입](../20261126-정정훈-AXYOURBODY프로토타입.html)을 기준으로 작성했다. CSS 전체의 적용 순서와 390px·1440px 브라우저 계산값을 확인했다. 아래 수치는 현재 구현값이며, 마지막 절의 정리 제안은 아직 구현하지 않은 항목이다.

기존 `DESIGN-calm-coach.md`는 Oura 관찰 자료의 보존 원문이다. 현재 제품을 재현하거나 확장할 때는 **이 문서를 먼저 사용**한다. 동작의 상세 계약은 [화면 명세](../SCREEN_SPEC.md), [행동 흐름](../docs/action-flow.md), [수용 기준별 감사](../docs/calm-coach-flow-audit.md)를 함께 따른다.

## 1. 제품의 시각적 태도

- **차분함:** 낮은 채도의 세이지 그린, 따뜻한 회백색, 흰 작업 영역을 사용한다. 큰 사진·장식 그래픽 없이 문장과 수치가 중심이다.
- **안내:** 중요한 화면의 상단에서 지금의 운동 상태와 다음 행동을 알려 준다. 버튼 이름으로 눌렀을 때 바뀌는 대상을 설명한다.
- **구분:** 계획, 시작 기준 계획, 실제 수행, 원본 기록은 서로 다른 정보다. 카드 제목·출처·상태 문구로 구분한다.
- **절제:** 주요 행동에만 짙은 초록색 면을 쓴다. 보조 행동은 옅은 면, 흰색 버튼, 텍스트 버튼으로 구분한다.
- **정직함:** 저장 전·저장됨·이번 실행에만 반영됨을 다르게 보여 준다. 고정 AI 예시와 실제 사용자 입력을 구분한다.

기존 화면을 확장할 때도 새로운 배지·카드·강조색을 먼저 추가하지 않는다. 사용자가 판단해야 할 상태와 행동을 먼저 정하고 기존 컴포넌트에 배치한다.

## 3. 서체와 숫자

### 글꼴

```css
font-family: AXNoto, -apple-system, BlinkMacSystemFont, "Segoe UI",
             "Noto Sans KR", "Malgun Gothic", sans-serif;
```

- `AXNoto`는 HTML에 WOFF2로 포함한 Noto Sans KR의 로컬 이름이다. 굵기 `100–900`, normal, `font-display: swap`으로 선언돼 있다.
- 외부 폰트 요청이 필요 없는 한국어 고딕체 구성이다. Oura 참고 자료의 Editorial New/AkkuratLL은 현재 제품에 사용하지 않는다.
- 일반 본문 행간은 `1.65`다. 버튼은 `1.5`, 페이지 제목과 다음 행동 제목은 `1.4`다.
- `.number`, `.mono`는 별도 모노스페이스 글꼴이 아니라 `font-variant-numeric: tabular-nums`를 적용한다.

## 4. 레이아웃과 반응형

### 공통 뼈대

```text
사이드바 또는 하단 메뉴
└─ 상단바: 제품명 / 현재 메뉴 / 프로필·저장 안내
   └─ 페이지 제목 + 짧은 설명 + 날짜/출처
      ├─ 현재 상태와 다음 행동
      ├─ 저장·변경·오류 안내
      ├─ 사용자가 판단하거나 편집할 내용
      ├─ 참고 기록 / 목표 / 원자료
      └─ 접힌 프로토타입 상태 시연
```

- 콘텐츠 컨테이너 최대 너비는 `1400px`이며 `border-box` 기준이다.
- 1440px에서는 왼쪽 사이드바 `236px`, 상단바 높이 `74px`, 콘텐츠 안쪽 여백 `30px 40px 60px`이다.
- 일반 상세 `.cols`는 `minmax(0,1.55fr) minmax(300px,1fr)` 두 열, 간격 `22px`이다.
- 운동 입력 `.workout-layout`은 `minmax(0,1.5fr) minmax(280px,1fr)`, 간격 `22px`이다.
- 설명용 오른쪽 `.stack` 카드는 투명 배경·구분선 위주다. 편집 카드와 같은 무게로 경쟁하지 않는다.

### 분기점

| 화면 너비 | 실제 처리 |
|---|---|
| ≥1500px | 콘텐츠 상단 40px, 일반 두 열 간격 28px, 카드 패딩 28px |
| 1101–1499px | 사이드바 236px, 콘텐츠 좌우 40px, 기본 두 열 |
| 851–1100px | 사이드바 200px, 콘텐츠 `26px 24px 55px`, 일반 상세의 보조 열 290px·간격 17px |
| 641–850px | 사이드바 190px, 일반 상세와 운동 입력이 한 열 |
| ≤640px | 사이드바 숨김, 하단 5개 메뉴, 상단바 65px, 콘텐츠 `22px 18px calc(125px + safe-area)` |

모바일에서는 다음 행동 버튼을 한 열 전체 너비로 배치한다. 계획의 가로 수치 표는 종목별 행으로 바꾸고 무게·횟수·세트 label을 각 값 위에 표시한다. 일반 폼 하단 행동도 한 열로 바꾼다.

체성분 요약은 `repeat(auto-fit, minmax(min(100%, 7em), 1fr))`을 사용한다. 글자가 커지면 열 수가 줄어든다. 모바일 날짜 필터는 한 줄에 한 필드를 배치한다. 고정 메뉴가 마지막 내용을 가리지 않도록 하단 여백과 safe-area를 유지한다.

### 간격·모서리·선

현재 코드는 단일 간격 토큰 체계로 정리돼 있지 않다. 다음 값을 역할별 기준으로 사용한다.

| 역할 | 현재 값 |
|---|---|
| 아이콘–글자 | 버튼 8px, 일반 내비게이션 12px |
| 작은 요소 사이 | 태그 7px, 일반 행동 버튼 9px |
| 폼 label–입력 | 6px |
| 카드 스택 | 18px |
| 주요 두 열 | 22px |
| 일반 카드 | 패딩 24px / 모바일 20px, 반경 10px / 모바일 12px |
| 다음 행동 패널 | 패딩 22px 24px / 모바일 18px, 반경 12px |
| 버튼 / 입력 / 태그 | 반경 8px / 7px / 5px |
| 필터 / 모달 | 반경 11px / 16px |
| 기본 구획선 | 1px 실선 |

일반 카드와 토스트에는 그림자를 쓰지 않는다. 현재 모바일 하단 메뉴에는 `0 -5px 18px #15251E10` 그림자가 남아 있다. 모든 표면을 같은 높이로 띄우지 않는다.

## 5. 컴포넌트

### 다음 행동 패널 — `.next-step`

제품의 핵심 안내 컴포넌트다. 페이지 제목 다음에 둔다.

1. 상태 또는 `지금 할 일` label.
2. 지금 할 행동을 설명하는 제목.
3. 수행 결과와 선택지를 설명하는 1~2문장.
4. 짙은 면의 주요 CTA와 보조 행동.
5. 필요한 경우 `계획 확인 → 운동 시작 → 수행값 입력 → 일지 저장` 단계 안내.

기본 패널 간격 16px, 모바일 14px. 주요 버튼은 최소 높이 48px이며 모바일에서 전체 너비다. 과거 이력보다 앞에 둔다.

### 버튼 — `.btn`

| 종류 | 형태 | 용도 |
|---|---|---|
| `.primary` | 주요색 면 + 흰 글자 | 다음 단계, 최종 저장, 운동 시작·종료 |
| 기본 | 흰 면 + 구획선 | 명확한 대안 행동 |
| `.soft` | 옅은 강조 면 + 진한 글자 | 참고 보기, 보조 저장, 재시도 |
| `.quiet` | 투명 면 + 보조색 글자 | 취소, 초기화, 보조 경로 |

공통 패딩 `9px 15px`, 아이콘 간격 8px, 최소 높이 44px. 주요 패널 안의 primary만 48px다. 뒤로 버튼과 프로필 도움말도 44×44px 이상이다.

한 과업 맥락에서 주요 CTA 하나를 구분한다. 행별 ‘계획대로 했어요’ 같은 보조 조작은 별도로 제공할 수 있다. 일반 버튼은 `type="button"`, 실제 폼 제출만 `type="submit"`으로 둔다. 취소가 저장을 실행해서는 안 된다.

### 입력과 선택

- 기본 입력: 흰 면, `#808779` 경계, 반경 7px, 최소 높이 44px, 패딩 `10px 12px`.
- textarea는 최소 높이 90px이고 세로 크기를 조절할 수 있다.
- 숫자 입력에는 단위·최소값·정수 조건을 명시한다. 선택 시간은 모르면 비워 둘 수 있게 한다.
- 체크박스 자체는 19px이고 넓은 `.check-row` label을 클릭 영역으로 쓴다.
- 몸 상태 1~5 버튼은 선택 여부를 면·글자·경계와 `aria-pressed`로 표시한다. 모바일에서는 줄바꿈을 허용한다.
- 검색·필터는 별도 옅은 셸 표면 안에 묶고 초기화 행동을 제공한다. 빈 결과도 필터를 해제할 수 있어야 한다.

### 계획 변경과 실제 수행

- `.plan-impact`: 편집 영역 바로 아래, 상단 구분선과 18px 여백으로 구분한다.
- 변경 전/후 표에는 **바꾼 종목만** 표시하고, 총 세트·예정 반복 수의 변화는 단순 합계로 설명한다.
- 저장 전에는 `저장 전 변경`, 저장 후에는 최근 변경 이유와 시각을 보여 준다.
- 실제 수행 행에는 `시작 기준 계획` 또는 `입력 시 참고 계획`, 수행 체크, 실제 무게·횟수·세트를 둔다.
- 계획값을 실제 값으로 복사하는 행동은 사용자가 종목별로 명시적으로 선택한다.
- 예정값과 수행값을 같은 값처럼 표시하거나 계획 저장으로 운동 완료 배지를 켜지 않는다.

### 안내·오류·태그

`.notice`는 반경 10px, 패딩 `15px 18px`, 아래 여백 20px의 지속 안내다. 일반은 옅은 녹색, 주의는 호박색, 오류는 붉은색 계열을 쓴다. 안내 안에서 재시도 행동을 제공할 수 있다.

태그는 짧은 상태·출처에만 쓴다. 기본 11px, 패딩 `3px 8px`, 반경 5px다. 본문을 모두 태그로 쪼개지 않는다. `가상 CSV`, `사용자 입력`, `읽기 전용`, `수행함`, `저장 전 변경`의 뜻을 혼합하지 않는다.

토스트는 짧은 확인용 보조 피드백이다. 저장 여부·오류·입력 제한은 패널이나 상태 줄에도 남긴다. 현재 토스트는 4.2초 뒤 사라지며 모바일 하단 위치는 88px이다.

### 모달

- 최대 너비 540px, 실제 너비 `calc(100% - 32px)`, 최대 높이 `90dvh`, 반경 16px.
- 제목·닫기와 본문 폼을 구분한다. 헤더 패딩 `22px 24px`, 폼 24px / 모바일 20px.
- 높이가 부족하면 내부를 스크롤한다. 확대해도 제출 버튼에 도달할 수 있어야 한다.
- Tab/Shift+Tab은 모달 안에서 순환한다. Escape와 닫기에는 동일한 미저장 확인 정책을 적용한다. 닫은 뒤 열었던 버튼으로 초점을 돌린다.

### 내비게이션·참고 정보

메뉴 순서는 **운동 계획 → 운동 일지 → 체성분 기록 → 지난 상담 → 운동 목표**다. 현재 항목은 옅은 녹색 면과 굵은 글자로 표시한다. 운동 목표는 현재 준비 중이며 비활성 이유가 이름에 포함된다.

상담 결론은 왼쪽 3px 강조선과 옅은 면으로 구분한다. 원문은 별도 영역에 남긴다. 체성분 그래프에는 날짜·수치·측정 조건과 대체 설명을 제공한다. 기록 포함 여부를 바꿔도 원 측정값을 숨기거나 바꾸지 않는다.

## 6. 상태를 디자인하는 규칙

| 상태 | 화면에서 설명할 것 | 주요 행동 |
|---|---|---|
| 기록 없음 | 운동 여부 미확인. 기록 없음은 미실행이 아님 | 오늘 계획 정하기 / 이미 한 운동 남기기 |
| 계획 편집 중 | 변경 전후, 반영 범위, 저장 전임 | 계획 저장하고 다음 단계로 |
| 계획 저장됨 | 계획만 저장됐고 운동 전임 | 운동 시작하기 |
| `active` | 운동 중. 임시 저장은 종료가 아님 | 운동 마치기 |
| `ended` | 종료 시각은 남았고 최종 일지 저장 전임 | 운동 일지 저장하기 |
| `logging` | 사후 수행 작성 중. 모르는 시각은 만들지 않음 | 운동 일지 저장하기 |
| `done` | 사용자가 확인한 실제 수행 기록 | 수행 기록 수정하기 |
| `skipped` | 사용자가 미실행이라고 명시적으로 남김 | 운동했어요 · 기록 바로잡기 |
| 저장 불가 | 이번 실행에만 반영됨 또는 저장 실패 | 원래 과업의 재시도 |
| 저장값 손상 | 정상 자료 보존·손상 부분 복구·원문 보존 상태 | 가능한 저장/복구 경로 |

편집을 시작한 화면에 이전 저장 성공 문구를 계속 남기지 않는다. 수정 중에는 저장 전 상태를 표시한다. 취소는 기존 저장 결과를 복원한다. 미실행→수행 정정도 최종 저장 전까지 기존 기록을 유지한다.

계획 수치 변경이 근육량·1RM의 개선을 예측한다는 표현은 쓰지 않는다. 실제 운동 여부는 사용자의 진술이며, 앱이 활동을 감지한 것처럼 보여 주지 않는다.

## 7. 화면별 조합

| 화면 / route | 주요 조합 | 핵심 디자인 책임 |
|---|---|---|
| 운동 계획 / `plans` | 다음 행동 + 필터 + 오늘 계획 + 최근 기록 | 최초 행동을 과거 기록보다 먼저 보여 줌 |
| 오늘 계획 / `today` | 다음 행동 + 저장 상태 + 수치·변경 영향 + 몸 상태 + 참고 영역 | 무엇을 바꾸고 어디에 반영되는지 표시 |
| AI 제안 / `ai` | 고정 예시 안내 + 비교표 + 적용/유지/직접 편집 + 근거 | 가상 제안과 실제 기록을 구분 |
| 운동 일지 / `log` | 현재 운동 상태 + 다음 행동 + 날짜별 원자료 | 이번 사용자 입력과 과거 CSV를 구분 |
| 수행 입력·일지 / `workout` | 상태별 CTA + 실제 수행 행 + 합계·시간·메모 | 시작·종료·최종 저장·정정을 구분 |
| 원본 운동 / `source-workout` | 읽기 전용 안내 + 종목별 원값 + 복귀 행동 | 편집 가능한 현재 일지로 돌아갈 길 제공 |
| 체성분 / `body` | 조건별 요약 + 필터 + 추세 + 날짜별 기록 | 동일한 조회 범위로 요약·그래프·목록 표시 |
| 체성분 상세 / `body-detail` | 날짜·측정 조건 + 값 + 추세 포함 체크·저장 | 비교 설정과 원 측정값의 차이를 설명 |
| 지난 상담 / `consults` | 작성 CTA + 검색·상대 필터 + 상담 목록/빈 상태 | 주제·날짜·출처로 찾을 수 있게 함 |
| 상담 상세 / `consult-detail` | 질문·결론·원문 + 계획 연결·해제 | 연결의 효과와 보존 대상을 표시 |
| 모달 | 상담 작성, 미실행 기록, 데이터 안내, 수면 누락 안내 | 과업 맥락 안에서 완료·취소·복귀 |

프로토타입 상태 시연은 화면 하단의 접힌 `details`로 둔다. 실제 사용자 과업보다 먼저 보이게 배치하지 않는다. 로딩·오류·빈 상태를 시연할 때도 기존 입력과 선택을 보존한다.

## 8. 한국어 문구와 정보 위계

- 대상+행동으로 쓴다: `운동 시작하기`, `운동 일지 저장하기`, `계획 연결 해제하기`.
- `계획 저장`, `운동 종료`, `일지 저장`을 모두 ‘완료’로 합치지 않는다.
- 정보 객체와 값을 구분한다: `체성분 기록`은 저장 자료, `체성분 측정값`은 숫자다.
- 효과를 구체적으로 말한다: ‘상담을 참고 자료로 연결해요. 연결만으로 무게·세트가 바뀌지 않습니다.’
- 오류는 원인/확인할 대상과 다음 행동을 함께 말한다. 사용자 잘못을 단정하거나 입력을 지우지 않는다.
- 표어·과도한 격려·추상적인 성장 약속으로 핵심 CTA를 밀어내지 않는다.
- 출처·날짜·단위·저장 한계는 가까운 곳에 두고, 상세 안내는 접을 수 있게 한다.
- 시연 기준일 `2026-10-29`와 실제 저장 시각을 구분한다.

## 9. 접근성과 동작

- 주요 조작은 44×44px 이상, 다음 행동 primary는 높이 48px 이상이다. 작은 체크박스는 label 영역을 포함한다.
- 현재 버튼·링크·입력·select·textarea의 실제 포커스 링은 `#208457`, 3px, offset 3px이다. 뒤쪽의 일반 `:focus-visible` 선언은 `#46634F`지만 앞쪽 요소별 선택자의 명시도가 높아 이 컨트롤에는 적용되지 않는다.
- 입력에는 보이는 label 또는 접근 가능한 이름을 제공한다. 오류에는 해당 입력 초점과 `aria-invalid`·`aria-describedby` 연결을 사용한다.
- 활성 메뉴는 `aria-current`, 선택 버튼은 `aria-pressed`, 상태 안내는 `role="status"`, 중요한 오류는 `role="alert"`로 표현한다.
- 화면 전환 후 제목으로 초점을 옮긴다. 모달 초점 순환·복귀, 한글 IME 조합 중 입력 보존을 유지한다.
- 본문 대비 4.5:1, 큰 글자 및 필요한 조작 경계 3:1을 검증 기준으로 삼는다. 색 이름만으로 합격을 단정하지 않는다.
- 320/390/768/1440px, 390px 글자 200% 확대에서 가로 넘침과 조작 접근성을 확인한다. 중요한 운동 상태·CTA는 390×844와 1440×900 첫 화면에 둔다.
- 로딩 원형 표시는 1초 회전이며 `prefers-reduced-motion: reduce`에서 애니메이션을 끈다. 장식 목적의 진입 애니메이션은 추가하지 않는다.

이 문서 작성에서는 390px·1440px 계산 스타일을 다시 확인했다. 전체 사용 흐름·110개 화면 조합의 기존 검증 범위와 제한은 [최종 보고](../docs/calm-coach-flow-final-report.md)에 있다. 실제 사용자 실험이나 모든 브라우저의 접근성 인증을 뜻하지 않는다.

## 10. 아이콘·브랜드·자산

- 아이콘은 인라인 SVG, 기본 21×21px, 선 두께 1.7, 둥근 끝/접합, `fill: none`, `stroke: currentColor`다.
- 모바일 하단 메뉴 아이콘은 19px, 빈 상태 아이콘은 36px다.
- 브랜드는 초록색 32×32px ‘AX’ 심벌과 `YOUR BODY` 텍스트 조합이다. 심벌 반경은 9px다.
- 사진·외부 아이콘 CDN·외부 웹폰트에 의존하지 않는다. 폰트·아이콘·시연 데이터가 단일 HTML 안에 있다.
- 원자료, 원본 시안, 참고 디자인은 [SOURCES.md](SOURCES.md)의 출처 구분을 유지한다.

## 12. 후속 디자인 작업에 붙여 넣을 지시

> AX YOUR BODY의 현재 제품 디자인은 이 문서를 기준으로 재현한다. 따뜻한 회백색 바탕, 흰 작업 카드, 낮은 채도의 초록색 주요 행동, Noto Sans KR을 사용한다. 각 화면은 현재 상태와 다음 행동을 먼저 보여 주고, 편집 대상·변경 영향·저장 결과를 구분한다. 데스크톱의 작업/참고 두 열은 모바일에서 한 열로 전환한다. 계획과 실제 수행을 합치지 않고, 오류·취소·빈 결과·저장 불가 상태도 같은 컴포넌트 체계로 구성한다. 새 기능의 데이터나 효과를 만들어내지 않으며, 기존 참고 브랜드의 사진·세리프체·파란 CTA를 이 제품의 현행 규칙으로 가져오지 않는다.
