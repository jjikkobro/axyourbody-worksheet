6. **닫기:** 최종 HTML 해시와 일치하는 결과만 최종 증거로 묶는다. 실패를 없애기 위한 테스트 삭제·skip·assert 완화는 금지한다. 요구 변경으로 테스트 의미를 수정할 때는 종전 기대·새 기대·근거·대체 검증을 기록한다.

### 상태 및 데이터 계약

- **서로 다른 객체:** 편집 초안, 저장한 오늘 계획, 운동 시작 당시 기준 계획, 실제 수행 내용, 읽기 전용 과거 원자료를 구분한다. 한 화면의 저장/취소로 다른 객체의 초안을 저장하거나 버리지 않는다.
- **운동 여부:** 기록 없음은 `미확인`, 시작은 `운동 중`, 종료는 `운동 마침·일지 저장 전`, 사후 입력은 `수행 내용 작성 중`, 최종 확인은 `운동했어요`, 명시적 미실행 저장은 `운동 안 했어요`다. 객체 이름은 바꿀 수 있으나 의미를 합치지 않는다. 앱은 사용자의 진술을 기록하며 신체 활동을 감지했다고 표현하지 않는다.
- **계획 편집:** 시작 전 종목별 무게·횟수·세트, 몸 상태·메모를 편집할 수 있다. 수치는 변경 전후와 총 세트·예정 반복 수의 산술 변화로 설명한다. 저장 전·저장 후를 구분하고 저장한 변경 이유·시각을 확인할 수 있게 한다. 몸 상태만 저장하면 수치 변경 이력을 만들지 않는다.
- **변경의 한계:** 계획 수정이 실제 수행 완료, 과거 기록 수정, 근육량/1RM의 예상 개선을 뜻하지 않는다. AI 고정 예시와 상담 연결도 동의 없이 계획·일지를 바꾸지 않는다. 사용자가 적용한 AI 예시는 계획 초안에 반영되고 별도 저장을 거친다.
- **수행 기록:** 시작 시 기준 계획을 고정하고 실제 값은 비워 둔다. ‘계획대로 했어요’처럼 사용자가 특정 종목을 확인한 때에만 계획값을 복사한다. 미체크 종목은 수행한 것으로 집계하지 않는다. 부분 수행도 저장할 수 있어야 한다.
- **입력 기준:** 수행한 종목의 무게는 유한한 0 이상 수, 횟수·세트는 1 이상 정수다. 종료/최종 저장에는 유효한 수행 종목 1개 이상이 필요하다. 시간은 선택이며 입력 시 0 이상 정수다. 임시 저장은 미완 입력을 보존할 수 있지만 완료로 표시하지 않는다. 공백·음수·소수 횟수·비유한 수·취소 후 잔류 값을 검사한다.
- **시간/중복:** 이미 한 운동을 나중에 기록할 때 모르는 시작·종료 시각을 만들지 않는다. 반복 클릭·재시도로 같은 시연일의 운동 객체나 변경 이력이 중복되지 않아야 한다. 별도 운동 추가는 이번 범위 밖이다.
- **정정:** 완료 일지의 실제 수행값 수정과 미실행→수행 정정은 초안에서 시작한다. 저장 전 기존 기록을 보존하고 취소 시 정확히 복원한다. 정정이 시작 당시 계획이나 원본 CSV를 바꾸지 않는다.
- **이탈·저장:** 계획/수행/체성분 설정/상담 폼/상담 연결 각각의 초안을 분리한다. 화면 이탈·뒤로·모달 닫기·Escape·새로고침의 미저장 경계를 검사한다. 브라우저 제약으로 이탈 경고를 보장할 수 없으면 자동 복구나 화면 내 안내 등 실제 가능한 보완을 구현하고 한계를 보고한다.
- **저장 장애:** 시연 저장 오류와 실제 localStorage 예외를 별도로 검사한다. 영속 저장 실패 시 입력을 유지하고 재시도 또는 ‘이번 실행에만 반영’ 상태를 명확히 표시한다. 이 상태를 ‘브라우저에 저장 완료’로 알리지 않는다. 새로고침 후 없는 기록을 미실행으로 간주하지 않는다.
- **저장값 복구:** 기존 정상 저장값은 유지하고, 손상 JSON·알 수 없는 상태·잘못된 행 타입/수치·불완전한 변경 이력을 주입해 검사한다. 화면이 깨지거나 무관한 정상 자료가 초기화되지 않아야 한다. 손상 원문을 조용히 덮어쓰지 말고 별도 보존 또는 명시적 복구 선택을 제공한다. 복구 실패도 성공으로 표시하지 않는다.

### 화면·문구 계약

- 주요 과업 화면은 `현재 상태 → 이 상태에서 가능한 행동 → 그 결과 → 참고 기록` 순서로 읽힌다. 전체 맥락의 주요 CTA는 하나로 구분하며 취소·다른 경로는 보조로 제공한다. 행별 조작은 유지할 수 있다.

- CTA는 대상과 동작을 말한다. ‘확인’, ‘완료’, ‘더 보기’만 있는 이름은 대상이 접근 가능한 이름과 주변 맥락에서 식별되는지 검사한다. `계획 저장`, `운동 종료`, `일지 저장`의 결과를 구별한다.
- 범위 안의 필수 행동을 비활성화하거나 설명 문구만 추가해 처리 완료로 세지 않는다. 준비 중 메뉴는 범위 밖일 때만 이유와 사용 가능한 경로를 제시한다. 읽기 전용 화면에는 편집 불가 이유와 돌아갈 경로를 둔다.
- AI slop은 문구/화면 위치와 사용자 방해를 짝지어 판정한다: 행동과 관계없는 표어, 반복 설명, 근거 없는 성과 약속, 대상을 숨긴 CTA, 동등한 강조로 묻힌 우선순위, 실제 저장과 다른 성공 알림. 단순 취향을 오류로 세지 않는다. 변경 전후 예시를 남긴다.

- 320/390/768/1440px에서 가로 넘침, 잘림, 가려진 조작을 확인한다. 키보드 Tab/Shift+Tab/Enter/Space/Escape, 초점 표시·모달 진입/복귀·폼 label·오류 연결·한글 IME 입력을 확인한다. 본문 대비 4.5:1, 큰 글자/조작 경계 3:1을 확인하고 핵심 터치 조작은 44×44px 이상으로 둔다. 폭 390px에서 글자 확대 200%에도 핵심 조작에 도달할 수 있어야 한다.
- AZTKS APPLY로 작업하고 최종 EVALUATE는 자체 검토임을 밝힌다. 5차원 등급은 증거·잔여 위험을 함께 제시한다. 점수는 G1~G6 합격을 대신하지 못한다.

## 3) 종료 조건 및 종료 방법

- **종료 조건 — 먼저 도달한 조건에서 구현 루프를 멈춘다.**
  - `COMPLETE = G1 ∧ G2 ∧ G3 ∧ G4 ∧ G5 ∧ G6`일 때만 `STOP REASON: COMPLETE`.
    - **G1 범위:** 실제 화면·조건부 상태·조작 인벤토리의 미분류 0건, 필수 항목의 미구현/미검증 0건. 제외 항목마다 4절 근거가 있으며 핵심 경로 제외는 0건.
    - **G2 행동:** 5절 AC01~AC20 전부 PASS. 각 행의 모든 하위 조건에 증거가 있고 실패·skip·보류 0건. 사용자 눈에 보이는 결과와 저장 상태를 모두 확인한다.
    - **G3 회귀:** 네 기존 검사 묶음과 추가한 의미 있는 검사가 최종 HTML에서 전부 통과. 결과 파일의 개별 항목까지 확인하며 외부 HTTP(S) 요청·처리되지 않은 JS 오류는 0건. 이전 버전 실패와 최종 실패를 분리한다.
    - **G4 표현:** 필수 화면의 실제 캡처·키보드 검토를 완료하고 2절 시각/문구 계약 위반 0건. 자동 넘침 검사만으로 화면 검토를 대체하지 않는다.
    - **G5 보존:** 원본 CSV·두 worksheet·원본 시안·HTML SOURCE/BASE/AI 불변. 정상 기존 저장값 호환, 초안 격리·정정·저장 장애·손상 복구 검사 통과. 범위 밖 변경 0건.

  - 실행 시작 후 **120분** 도달 → `STOP REASON: TIME_CAP`. 105분부터 새로운 개선 착수를 중지하고 마지막 15분은 검증·기록에 배정한다. 이미 시작한 검사도 시간 한도를 넘기지 않도록 종료하고 미완료를 남긴다.
  - 평가-진행 **40 turns** 도달 → `STOP REASON: TURN_CAP`. turn은 `/goal` 평가자가 점검하는 메인 에이전트 응답 사이클이며 도구 호출이나 테스트 케이스 수가 아니다. 이 값은 이번 재설계의 기본 실행 예산이며 사용자 요청 시 조정한다. 토큰 예산은 별도로 부여하지 않는다.
  - 동일 원인의 검증/환경 실패가 **새 근거 없이 3회** 반복되고 가능한 독립 작업도 소진 → `STOP REASON: BLOCKED`. 마지막 원인·시도·필요한 해소 조건을 남긴다. 반복 재실행으로 예산을 소비하지 않는다.
  - 계약 달성에 외부 서비스·파괴적 데이터 전환 등 범위 밖 결정이 필수이고 독립 작업도 소진 → `STOP REASON: SCOPE_DECISION`. 구체적인 결정 대상과 준비된 대안을 제시한다.
  - 사용자 중단 요청 → `STOP REASON: USER_STOP`. 위 한도로 종료하면 ‘완료’로 부르지 않으며 남은 AC/결함 ID를 명시한다. 사소한 장식 개선을 위해 합격 이후 반복하지 않는다.
- **종료 방법:**
  1. 실행 폴더에 `baseline/`, `final/`, `evidence.json`, `report.md`를 남긴다. evidence에는 시작/종료 시각, HEAD, 기준/최종 HTML 해시, 각 명령·exit code·결과 경로·pass/total·실패/skip, AC별 판정/증거, G1~G6, 보존 비교, 잔여 제한, STOP REASON을 기록한다. 자동으로 검사하지 않은 수동 캡처 검토는 검토자=본 에이전트·검토 위치·발견 사항을 명시한다.
  2. 6절의 실제 명령을 실행한다. `git diff --check`의 exit 0, 전체 변경 목록과 이번 실행 변경 목록의 구분, 보존 비교 결과를 대화에 남긴다. 미추적 수정 파일도 누락하지 않는다.
  3. 회귀별 최종 pass/total·실패·skip, AC 통과/전체, G1~G6, 뷰포트/상태 범위, 외부 요청/JS 오류 수, 최종 해시, `STOP REASON`을 **대화에 직접** 남긴다. 파일 링크만으로 완료를 주장하지 않는다.
  4. `docs/calm-coach-flow-final-report.md`에 변경 전후 대표 흐름·검사 증거·잔여 한계를 연결하고 명세와 README를 갱신한다. 이전 보고는 이전 버전 결과로 보존한다. 실제 사용자 관찰은 하지 않았다면 ‘미실시’로 적고 성공률·사용성 향상을 만들어내지 않는다.
  5. 대화 보고는 1,200자 이내를 목표로 하되 실패·미검증·중단 이유를 잘라내지 않는다. 자세한 목록은 파일로 연결한다.

## 4) 기타 제약조건

- 로컬 단일 HTML·오프라인 시연을 유지한다. 프레임워크 이관, 계정/서버/실제 AI/센서/코치 통신, 종목 추가·교체, 여러 날짜의 새 운동 생성, 목표 편집, 수면 신규 입력은 이번 범위 밖이다. 운동 일지의 현재 계약 완성은 범위 안이다.
- 시연 기준일 `2026-10-29`와 실제 저장 시각을 구분한다. PC의 현재 날짜를 시연 과거 데이터와 섞거나 기준일 이후 자료를 과거 판단의 근거로 사용하지 않는다.
- 원자료·worksheet·Stitch 원본과 기존 미커밋 작업을 보존한다. 변경 대상 밖 파일을 덮어쓰거나 git reset/clean으로 정리하지 않는다. 복구나 마이그레이션을 핑계로 정상 저장 자료를 초기화하지 않는다.
- 실제 운동/건강 결과, 실제 코치 답변, 독립 리뷰, 실제 사용자 테스트를 생성하지 않는다. AI의 고정 예시임을 숨기지 않는다.
- 커밋·푸시·PR·배포·공유·Figma 쓰기·제출·메시지 발송은 하지 않는다. 기존 도구를 우선하고 새 유료 서비스·원격 의존성을 추가하지 않는다. 임시 로컬 검증 환경 수리는 예산 안에서 허용한다.
- 모든 핵심 경로는 이 목표 안에서 해결한다. ‘준비 중’, 임의 범위 축소, 테스트 통과 수 증가, AZTKS 자체 점수로 미완성을 감추지 않는다.
