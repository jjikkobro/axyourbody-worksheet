# calm-coach-flow 목표 재검토

2026-11-27 · 문서 설계 검토. 이번 작업은 목표·검토 근거·원문 보존에 한정하며 제품을 수정하거나 `/goal`을 실행하지 않았다.

## 결론

기존 목표는 ‘노출된 조작을 검사한다’에 집중해 서비스가 제공해야 할 행동 자체의 누락을 잡기 어려웠다. 최신 요구는 운동 여부를 확인하고, 바꿀 내용을 선택하고, 변경 영향을 이해한 뒤 실제 수행을 남기는 흐름이다. 새 목표는 이를 하나의 종단 흐름으로 묶고 20개 수용 시나리오와 6개 완료 게이트로 판정한다.

## 코드에서 발견한 추가 검증 후보

다음은 소스 관찰에 근거한 **검증 후보**다. 실제 UI로 결함을 재현한 결과가 아니므로 발생 여부를 확정하지 않는다.

- HTML의 저장값 로딩부는 `workout` 상태/배열/길이를 검사하지만 각 행의 수치·형태까지 검사하지 않는다. `planChanges`는 배열 여부만 확인한다. 잘못된 내부 항목을 주입할 때 렌더와 저장의 안전성을 AC15에서 확인한다.
- 손상 JSON의 catch는 초기 상태로 복귀하고 다음 저장을 허용한다. 손상 원문 보존과 사용자의 복구 선택이 충분한지 확인한다. 기존 TF Q03의 ‘다시 저장 가능’만으로 자료 보존을 증명할 수 없다.
- `planLocked()`는 운동 객체가 있으면 true다. 시작 후뿐 아니라 미실행·정정 상태에서 몸 상태/메모 등 편집 UI가 저장 가능한지 AC12로 조사한다.
- `beforeunload`는 전역 `dirty`를 확인한다. 상담 폼·연결·체성분·운동 초안에서 이 값과 실제 편집 상태가 일치하는지 AC16으로 확인한다.
- `persist()`는 저장 예외 시 세션 한정 상태로 전환한 후 true를 반환한다. 각 호출부의 문구와 재방문 상태가 영속 저장으로 오해되지 않는지 AC14로 확인한다.

## 설계 결정과 예산

- 제품 목표를 여러 독립 과제로 나누지 않았다. 디자인·문구·상태 저장·검사는 모두 ‘오늘 운동 행동 흐름 완성’이라는 동일한 완료식의 조건이다.
- ‘모든 화면’을 무한 기능 확장으로 해석하지 않았다. 현재 계획·일지·체성분·상담과 그 조건부 상태를 포함하고 실제 AI/계정/서버·다른 날짜 운동 생성·새 종목/목표/수면 입력은 제외했다.
- 가정: 시연 기준일과 단일 HTML 형식을 유지한다. 이는 현재 구현과 사용자의 차분한 운동 코치 방향을 잇는 선택이며 실제 서비스 출시 목표는 아니다.
- 예산 기본값은 120분 또는 40 평가 turns로 제안했다. 기존 6라운드는 실행량을 정의하기 어려워 대체했다. 시간 상한이 먼저 오면 미완료로 보고하며, 마지막 15분은 검증/보고에 사용한다. 별도 토큰 수는 임의로 설정하지 않았다.
- 자율성은 수정 횟수 대신 영향으로 제한한다. 되돌릴 수 있는 로컬 UI/동작/호환 수정은 진행하고, 외부 연결·원자료 변경·배포는 이번 범위에서 제외한다.
- 기존 기능과 기준을 맞추기 위한 최소한의 로컬 스키마 보완은 허용한다. ‘데이터 모델 변경 금지’를 그대로 두어 수행 기록/복구 보완을 막지 않는다.

## 이번 문서 수정의 검증

- 필수 4개 절: 4/4, 수용 시나리오 AC01~AC20: 중복/누락 없이 20/20.
- 두 문서의 Markdown 상대 링크: 모두 실제 파일로 연결됨.
- 목표에 포함한 세 Bash 블록: `bash -n` 문법 검사 통과.
- JSON 판정 코드를 임시 폴더의 기존 결과 복사본으로 실행: 통과. TF의 개별 결과 하나를 실패로 바꾼 복사본: 실패 종료 확인. 이는 **판정 코드의 검증**이며 제품 재검증이 아니다.
- `git diff --check`: exit 0. 미추적 목표 문서도 별도로 줄 끝 공백 검사 통과.
- HTML SHA-256: 위 기준과 동일. 이번 수정 파일은 목표, 본 검토 문서, 기존 목표 보존본 3개다.
- 새 목표의 G1~G6 및 AC01~AC20: **실행 전·미판정**. 기존 통과 결과를 새 목표 달성으로 인정하지 않는다.
