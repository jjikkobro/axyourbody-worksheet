# 계획 확인에서 운동 일지까지 이어지는 행동 흐름

2026-11-27 · 기존 차분한 운동 코치 시각 방향 유지

후속 수용 기준 실행 결과는 [최종 검증 보고](calm-coach-flow-final-report.md)를 따른다. 몸 상태 전용 저장·취소, 상담 연결 해제, 손상 저장값 복구, 취소 버튼 제출 방지, 키보드·확대 대응은 후속 변경이다. 아래 검사 숫자는 당시 버전의 이력이다.

## 수정한 문제

앞선 구현은 계획·체성분·상담의 기존 버튼 동작을 확인했지만, 계획 저장 후 사용자가 운동을 시작하고 실제 수행 결과를 남기는 경로가 없었다. 따라서 당시 자동 검사 통과를 서비스의 전체 행동 흐름 완성으로 해석한 것은 적절하지 않았다.

사용자는 운동 여부, 바꿀 수 있는 내용, 변경의 영향, 지금 할 행동이 보이지 않는다고 지적했다. 이번 변경은 그 피드백에 따라 기존 7개 화면 범위를 확장해 운동 실행과 일지를 연결한다. 과거의 ‘운동 일지는 범위 밖’ 조건은 이번 요청에서 더 이상 적용하지 않는다.

첫 진입과 계획 상세의 주요 CTA는 모바일·데스크톱의 첫 화면에서 확인할 수 있다. 운동 일지 메뉴는 활성화했다. 원본 운동 이력은 이번에 입력하는 일지 아래의 읽기 전용 영역으로 구분한다.

## 무엇을 바꿀 수 있고 어떤 영향이 있나

### 운동 시작 전 계획

- 종목별 무게·횟수·세트, 오늘 몸 상태·메모를 바꿀 수 있다.
- 수치 변경은 입력하는 동안 변경 전후 표에 표시한다. 총 세트와 예정 반복 수의 변화는 입력값의 단순 합계다.
- 예: 백스쿼트 `102.5kg · 5회 × 5세트`를 `90kg · 5회 × 4세트`로 바꾸면, 전체 예정 세트는 `11 → 10`, 예정 반복 수는 `79 → 74회`다.
- 변경 이유는 직접 조정·몸 상태·시간·장비 중 사용자가 선택한다. 저장 시 변경 시각·이유·변경 전후 값을 남긴다. 몸 상태만 저장한 경우 운동 수치 변경 내역을 만들지 않는다.
- 계획 변경은 오늘 예정 내용을 바꾼다. 운동 완료·과거 기록 변경·실제 수행값 변경으로 처리하지 않는다. 골격근량·1RM에 미칠 효과를 예측하거나 약속하지 않는다.

### 운동 시작 후 실제 수행

- 시작 당시 계획을 별도로 보관한다. 이후에는 기준 계획을 덮어쓰는 대신 일지에서 실제 수행값을 바꾼다.
- 종목별 수행 여부를 직접 표시하고 실제 무게·횟수·세트를 입력한다. ‘계획대로 했어요’를 누른 종목만 사용자가 확인한 계획값으로 채운다.
- 체크하지 않은 종목은 수행한 것으로 저장하지 않는다. 한 종목만 했어도 그 종목의 수행값을 남길 수 있다.
- 운동 시간과 메모는 선택 입력이다. 모르는 시간을 자동 계산해 채우지 않는다.
- 완료한 일지도 수정하거나 수정을 취소할 수 있다. 수정은 해당 일지에만 반영하며 기준 계획과 원본 CSV는 보존한다.

## 상태와 저장 의미

| 저장 상태 | 화면 표시 | 운동한 것으로 확정했나? |
|---|---|---|
| 운동 객체 없음 | 운동 여부 미확인 | 아니오. 기록 없음은 미실행이 아님 |
| active | 운동 중 | 아니오. 시작 버튼만 누른 상태일 수 있음 |
| ended | 운동 마침·일지 저장 전 | 종료는 사용자가 확인했지만, 최종 일지는 저장 전 |
| logging | 수행 내용 작성 중 | 이미 한 운동을 남기는 중. 아직 일지 저장 전 |
| done | 운동했어요 | 사용자가 수행 종목·수치를 확인해 일지 저장 |
| skipped | 운동 안 했어요 | 사용자가 운동하지 않았다고 명시적으로 저장 |

- 수행 내용 임시 저장은 운동 종료나 최종 일지 저장을 대신하지 않는다.
- 종료·최종 저장은 수행 종목 1개 이상과 해당 종목의 유효한 수치를 요구한다. 무게는 0 이상, 횟수·세트는 1 이상의 정수다. 실제 운동 시간은 선택이며 입력하면 0 이상의 정수다.
- 이미 한 운동을 바로 남길 때 시작·종료 시각을 만들지 않는다. 일지 저장 시각만 남긴다.
- 같은 계획에는 이번 운동 기록 1개를 연결한다. 시작 버튼을 다시 호출해도 새 운동을 중복 생성하지 않는다.
- 운동하지 않았다는 기록을 바로잡을 때는 저장 전까지 기존 기록을 유지한다. 초안을 취소할 수 있다.

## 저장·오류·복귀

미저장 계획은 먼저 저장 또는 취소해야 실제 운동 작성이나 미실행 기록으로 이동한다. 수행값을 작성하다 이탈하면 폐기 여부를 확인한다. 거절하면 입력을 보존하고, 수락하면 마지막 저장 내용으로 복원한다.

시작·임시 저장·종료·최종 저장·미실행 기록의 오류에는 입력을 보존한 재시도 경로가 있다. 브라우저 저장이 불가능하면 이번 실행에만 반영한다고 표시한다. 저장 불가 후 새로 열었을 때 기록 부재를 ‘운동 안 했어요’로 바꾸지 않는다.

요약과 HTML SHA-256은 [summary.json](../verification/action-flow/summary.json), 새 운동 흐름의 개별 결과는 [lifecycle-results.json](../verification/action-flow/lifecycle-results.json)에 남겼다. 대표 화면: [운동 시작 CTA](../verification/action-flow/390-ready.png), [변경 전후와 영향](../verification/action-flow/1440-plan-change.png), [완료한 운동 일지](../verification/action-flow/390-done.png).

- `action-flows.cjs`: 첫 화면 CTA, 변경 전후·영향, 시작·종료·완료 분리, 직접 기록, 미실행·정정, 수행값 수정·취소, 오류·재시도, 저장 불가, 원본 보존, 모바일을 검사한다.
- `calm-coach-flows.cjs`: 기존 계획·체성분·상담 회귀. 운동 일지 활성화와 주요 CTA 변경에 맞춰 기대값을 갱신했다. 기존 버튼 동작 커버리지와 신규 운동 동작 커버리지는 결과를 합쳐 확인한다.
- `aztks-followup.cjs`: 기존 9개 회귀. 결과 경로를 환경 변수로 지정할 수 있게 해 과거 결과를 덮어쓰지 않는다.
- `tf-30-simulations.cjs`: 기존 30개 시나리오. 모바일 CTA 선택자는 이전 화면의 `.quick-actions`와 새 화면의 `#next-action`을 모두 지원한다. 선택자 변경 때문에 기준 화면 점수가 낮아진 것을 개선 효과로 보고하지 않는다.

이번 검증은 오프라인 Chromium 스크립트 검사와 캡처 검토다. 실제 사용자가 흐름을 이해했는지, 운동을 실제로 수행했는지에 대한 독립 관찰은 아니다. 앱의 운동 여부는 사용자가 직접 남긴 사실이다.
