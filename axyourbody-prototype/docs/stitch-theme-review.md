# Stitch 세 테마 검토

검토일: 2026-11-26 · 대상: m-athlete · 범위: 현재 Stitch에 있는 과업 1의 화면 9개

## 결론

**디자인 기준안은 Clear Guidance를 권한다.** 밝은 바탕·강한 제목 위계·구분된 비교표가 무게·세트와 근거를 읽고 결정하는 과업에 잘 맞는다. 이는 화면과 코드에 대한 전문가 검토 의견이며 사용자 테스트 결과가 아니다.

**동작 구현의 참고 기준은 Precise Training으로 분류한 어두운 테마다.** AI 제안 선택 전달과 컨디션 선택 표시가 다른 두 테마보다 완성되어 있다. 시각 디자인 추천과 동작 완성도를 구분한다.

통합 제안: Clear Guidance의 읽기·비교 구조 + Calm Coach의 여유 있는 간격·카드 표현 일부 + Precise Training의 선택 전달·상태 처리 코드를 참고한다. 아직 통합하거나 원격 화면을 수정하지 않았다.

## 확인한 자료와 한계

- Stitch 프로젝트: https://stitch.withgoogle.com/projects/1302419695509867707 (`프로젝트 프로토타입 제작`).
- `list_screens`, `get_screen`, `download_file`로 기존 HTML을 읽기 전용 다운로드했다.
- Calm Coach 3개, Clear Guidance 3개, 테마명 없는 3개. 이름 없는 화면은 `#010102` 바탕과 `#5e6ad2` 강조색을 사용하므로 Linear 기반 Precise Training으로 **추정 분류**했다.
- 다운로드 원본: `../stitch-review/{테마}/S01.html`~`S03.html`. 파일 내용은 수정하지 않았다.
- 화면 ID·원본 resource 매핑: `../stitch-review/screens.json`.
- 1280×1024에서 화면 9개 렌더링 및 시각 확인. 390×844에서는 S02만 추가 확인했다.
- 다운로드 HTML의 원래 상대경로를 로컬 라우팅으로 대응시켜 S03→S02 선택 전달·S02 저장/실패/재시도·컨디션 선택을 확인했다. Stitch 웹 에디터의 연결 동작을 직접 시험한 결과와는 구분한다.
- 렌더링 및 상호작용 증거: `../stitch-review/render-evidence.json`, `../stitch-review/interaction-evidence.json`.
- 실제 사용자 대상 성공률·소요 시간은 측정하지 않았다. 기능 확인을 사용자 테스트 성공률로 환산하지 않는다.
- 현재 프로젝트에는 S01~S03만 있다. 과업 2·3의 S04~S07와 부수 A01은 비교 대상에 없다.

Calm Coach·Clear Guidance의 S03 선택 버튼은 S02로 이동만 한다. S02도 AI 선택을 읽는 코드가 없다. Precise Training 추정 테마는 `sessionStorage`의 `ax_s03_choice`를 읽고 제안 값을 전달한다. 다만 이 구현도 새로고침·다른 계획 간 선택 격리와 오래된 선택값 정리 여부는 별도 보완 검토가 필요하다.

이 검토에서 확인한 저장은 화면 내 시연 동작이다. 실제 서버 저장·장기 보존을 확인한 것은 아니다.

## 공통 수정 우선순위

### 1. 페르소나 목표 우선순위 복원

세 테마 모두 `하체 근력 유지 → 하이록스 레이스 완주`라는 시연 목표를 사용한다. 원래 프로필의 다음 순서와 다르다.

1. 골격근량 36.2kg → 37.5kg
2. 백스쿼트 실측 1RM 115kg → 125kg
3. 하이록스 기록 유지, 다른 목표를 방해하지 않기

운동 계획 샘플은 가상임을 표시할 수 있지만, 핵심 페르소나의 목표를 다른 목표로 바꾸면 판단 기준이 달라진다. 목표 영역과 AI 참고 근거를 함께 수정해야 한다.

### 2. AI 선택 전달과 사용자 입력 구분

- 밝은 두 테마의 S03 선택 결과가 S02에 전달되도록 보완한다.
- S02의 컨디션 4가 미리 선택되어 있고 S03에 `사용자 입력`으로 표시된다. 사용자가 입력하기 전이면 미입력으로 보여 주거나 가상 시연 입력임을 명시해야 한다.
- CSV의 수면 컨디션과 오늘의 사용자 입력을 같은 출처로 처리하지 않는다.
- 밝은 두 테마의 컨디션 버튼은 선택 표시도 갱신하지 않는다.

### 3. 모바일 표시

- 390px에서 S02의 전체 페이지 가로 넘침은 없지만 표 내부의 운동명 열이 좁아 종목명이 세로로 여러 줄 나뉜다. 이전 RPE는 가로 스크롤 영역에 들어가 처음에는 일부만 보인다.
- 모바일에서는 종목명·무게·횟수·세트를 한 묶음의 카드로 제시하는 안을 권한다.
- 5개 메뉴는 위쪽 가로 스크롤 줄로 표시되어 처음 화면에 전부 드러나지 않는다. 이동 가능성을 알리거나 다른 모바일 메뉴 구성을 비교할 필요가 있다.
- 컨디션 1~5가 두 줄로 나뉜다. 하나의 묶음으로 읽히도록 폭·배치를 조정한다.

### 4. 한글 폰트 대체 규칙

검토용 Linux 브라우저에서는 일부 `font-mono` 영역의 한글(예: 시간 단위·유지)이 네모로 표시됐다. `Source Code Pro, monospace` 뒤에 한국어 대체 글꼴이 지정되지 않은 점과 이 환경의 기본 한글 폰트 부재가 함께 영향을 줄 수 있다. 모든 사용자 환경의 오류로 단정하지 않는다. 한글 단위·설명은 Noto Sans KR로, 숫자만 등폭으로 분리하는 안을 권한다.
