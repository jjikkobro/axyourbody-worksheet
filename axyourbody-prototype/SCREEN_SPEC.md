# AX YOUR BODY · 공통 화면 명세

작성일: 2026-11-26 · 대상: 가상 프로필 `m-athlete` · 버전: 1.0

## 1. 목적과 결정 상태

서로 다른 세 디자인으로 같은 과업을 구현하고 비교·통합하기 위한 공통 기능 명세다.

- **확정**: 핵심 과업 1~3, 필수 독립 화면 7개, 부수 제안 화면 1개, 완료 지점, 화면별 핵심지표, 검색·입력·연결 패널의 내부 기능 분류. 근거: `docs/grip/GRIP_REGISTER.md` T1~T7.
- **작성안**: 이번 명세의 화면 ID, 세부 영역 구분, 확인 절차, 빈·오류·로딩 처리의 구체 표현. 기존 결정과 일치하도록 작성했으며 별도 사용자 검증을 마친 것은 아니다.
- **미정**: 기준 배치, 각 테마의 최종 디자인, 과업 2·3 상태 표현의 최종 선택, 테스트 목표 수치, 실제 테스트 결과, 저장 기술·보존 기간.
- 과업 1의 상태 4종은 `context/screen-flow.md`에 정리한 설계 사례를 따른다. 오류·로딩은 관찰된 실제 사건이 아니다.
- 이 명세는 앱 구현 결과나 사용성 테스트 완료 보고가 아니다.

## 2. 참조와 적용 순서

1. `context/service-structure.md`: 서비스 전체의 객체·관계·용어·메뉴·하지 말 것.
2. 이 문서: 이번 시안 범위인 핵심 과업 1~3의 화면과 필수 동작.
3. `context/screen-flow.md`: 과업 1의 기본 흐름·갈림길·화면·상태. 과업 2·3 흐름은 이 문서 4절에 있다.
4. `worksheet.md`, `docs/grip/GRIP_REGISTER.md`: 결정 근거와 원문 기록.
5. `design/DESIGN-{테마이름}.md`: 테마별 시각 표현. 기능·용어·데이터·사용자 결정권을 바꾸지 않는다.

서비스 전체 설명서의 과업 4~7과 주 메뉴 5개는 유지하되 이번 필수 화면 구현으로 확대하지 않는다. 문서 사이에 충돌이 발견되면 해당 결정을 확인하고 임의로 바꾸지 않는다.

## 4. 과업 흐름과 완료 조건

### 과업 1 · 오늘 하체 훈련 결정

- 기본: S01 → S02 → S03 → S02(저장 내용 확인).
- 직접 결정: S01 → S02 → 내부 편집/유지 선택 → 저장 → S02 확인. AI 제안 검토를 강제하지 않는다.
- AI 검토: S03에서 유지·수정 적용·직접 변경 중 사용자가 선택한다. 변경 내용을 저장한 뒤 S02에서 확인한다.
- 완료: 사용자가 정한 무게·세트 유지 또는 변경이 저장되고 S02에서 선택 내용과 일치함을 확인한다.
- 운동 시작·수행·운동 일지 저장은 후속 행동이며 이번 과업 완료에 포함하지 않는다.

### 과업 2 · 측정 조건을 구분한 체성분 비교

- 기본: S04(목록·추세) → S05 → 포함/제외 설정 저장 → S04(반영 확인).
- 조건 필터는 S04 내부 기능이다. 비교 전용 화면을 추가하지 않는다.
- 완료: 측정 조건을 확인해 추세 포함 여부를 저장하고 목록·추세의 반영 여부를 확인한다.
- 포함·제외 어느 선택도 가능하다. 제외해도 원본 측정값·측정 조건은 보존한다.

### 과업 3 · 지난 상담을 오늘 계획에 연결

- 기본: S06 → S07 → 내부에서 오늘 운동 계획 선택 → 연결 저장 → 연결한 계획 확인.
- 완료: 원하는 상담의 결론 또는 답변 원문, 맥락·출처를 확인하고 선택한 오늘 계획에 연결을 저장한 뒤 대상을 확인한다.
- 연결은 참고 자료 연결이다. 무게·세트 변경, 운동 시작·완료를 의미하지 않는다.
- A01은 새 상담이 필요할 때 쓰는 부수 제안이며 기본 찾기·연결 과업에 필수로 넣지 않는다.

## 5. 공통 표시·데이터 규칙

- 주 메뉴 이름·순서: 운동 계획 → 운동 일지 → 체성분 기록 → 지난 상담 → 운동 목표. 현재 선택을 색과 글자/선택 표시로 함께 구분한다.
- 운동 일지·운동 목표의 독립 상세 화면은 이번 범위 밖이다. 미구현 메뉴는 준비 중임을 알리고 작동하는 화면처럼 보이게 하지 않는다.
- 상세에 화면 이름·날짜·뒤로 가기를 둔다. 목록 복귀 시 검색어·조건·날짜·스크롤 등 조회 맥락을 보존한다.
- 작성 중 이탈하면 저장 여부를 선택하게 한다. 실패 시 작성 내용과 선택을 보존한다.
- AI 제안/요약, 사용자 입력, 코치 원문, 계산값, 가상 예시를 구분해 표시한다.
- `body.csv`, `workout.csv`, `sleep.csv`, `meal.csv`는 원본 그대로 읽는다. 값이 없으면 없음/미확인으로 표시한다.
- CSV에는 실제 운동 기록이 있지만 미래 운동 계획, 상담 원문, 계획 변경 이유, 목표 변경 이력은 없다. 이들을 실제 데이터로 생성하지 않는다.
- 시안 동작 확인에 계획·상담 샘플이 필요하면 세 테마가 동일한 **가상 시연용 샘플**을 사용하고 출처·작성 주체를 표시한다. 샘플의 무게·세트·날짜를 실제 예정 계획처럼 단정하지 않는다. CSV에서 가져온 실제 수행값은 원래 의미를 유지한다.
- 상담 샘플은 실존 코치 발언으로 표시하지 않는다. 빈 상태를 별도로 제공한다.
- 과거 날짜를 기준으로 설명할 때 이후 날짜의 기록을 근거에 포함하지 않는다.
- 상태 라벨은 색과 글자를 함께 쓴다. 오류 시 원인 또는 확인 가능한 범위와 다음 행동을 안내한다.

## 6. 화면별 명세

### S01 · 운동 계획

**목적:** 날짜별 계획에서 오늘 하체 계획을 찾는다.

- 진입: 주 메뉴 운동 계획. 복귀: S02의 뒤로 가기.
- 표시: 조회 날짜, 예정 종목, 처리 상태, 계획별 상세 진입점. 계획값은 실제 제공값 또는 표시된 시연용 샘플만 사용한다.
- 내부 기능: 날짜·처리 상태·예정 종목 필터.
- 행동: 날짜와 계획 선택 → S02. 선택한 계획 ID·날짜를 유지한다.
- 성공 조건: 지정한 날짜의 하체 계획 상세를 정확히 연다.
- 지표: 성공 테스트 수 ÷ 해당 찾기 테스트 시도 수 × 100.
- 상태 작성안: 계획 없음은 실제 데이터 부재와 시연 상태를 구분하고, 날짜 바꾸기/이전 날짜 보기 등 가능한 다음 행동을 제공한다. 계획 없음이 운동하지 않았다는 뜻은 아니다.

### S02 · 오늘 운동 계획

**목적:** 예정 내용과 참고 기록을 보고 유지·변경을 결정하고 저장 결과를 확인한다.

- 진입: S01, S03에서 복귀. 날짜·선택한 계획 맥락을 유지한다.
- 표시: 예정 무게·횟수·세트, 목표 우선순위, 관련 전날 운동·수면, 오늘 몸 상태, 연결한 상담, 선택 후 저장된 계획. 누락값은 표시한다.
- 내부 기능: 오늘 몸 상태 입력, 무게·세트 편집. 필수 입력 항목·검증 수치 범위는 구현 전 확인하고 임의의 의학적 기준을 넣지 않는다.
- 행동: `운동 계획 바꾸기`로 편집, `이 계획으로 운동하기`로 사용자 선택 확인·저장. 이 버튼은 실제 운동 시작을 뜻하지 않는다. AI 제안 보기 → S03.
- 유지 선택도 명시적으로 저장·확인할 수 있어야 한다. 저장 성공 시 선택 내용·무게·세트를 다시 보여준다.
- 지표: 선택 내용과 저장된 무게·세트의 일치를 확인한 테스트 수 ÷ 해당 결정 테스트 시도 수 × 100.
- 상태: 과업 1 수면 누락·저장 오류 사례는 7절을 따른다.

### S03 · AI가 제안한 운동 계획

**목적:** 제안·근거·한계를 구분해 사용자가 오늘 계획을 결정하도록 돕는다.

- 진입: S02. 복귀: S02. 조회만으로 계획을 바꾸지 않는다.
- 표시: AI 제안, 참고한 목표·운동·수면·몸 상태와 날짜, 적용 한계, 필요한 전문가 확인 안내, 사용자의 선택.
- 세 테마에서 제안 내용과 근거 데이터는 같아야 한다. 프로토타입은 생성 결과를 시연용 예시라고 표시하며 실제 상담·진단으로 표시하지 않는다.
- 행동: 기존 계획 유지, 제안을 검토해 수정 적용, 직접 변경. 선택한 내용을 S02에서 저장·확인한다.
- 근거가 부족한 상태에서 단정적인 강도 변경을 만들지 않는다. 사용자 판단을 돕는 설명과 직접 결정 경로를 제공한다.
- 지표: 제안 내용·참고 기록·적용 한계를 모두 정확히 짚은 테스트 수 ÷ 해당 확인 테스트 시도 수 × 100.
- 제안을 거절해도 이해 기준을 충족하면 성공이다. 클릭·열람·수락으로 이해 성공을 대신하지 않는다.
- 상태: 과업 1 로딩·측정 조건 차이 사례는 7절을 따른다.

### S04 · 체성분 기록

**목적:** 날짜별 측정과 측정 조건을 찾고 같은 조건의 추세를 비교한다.

- 진입: 주 메뉴 체성분 기록. S05에서 설정 저장 후 복귀한다.
- 표시: 날짜, 체중·골격근량 등 제공 측정값과 단위, 측정한 때의 상태, 추세 포함 여부, 목록과 추세.
- 내부 기능: 측정일 범위·측정 조건·그래프 포함 여부 필터. 한 화면에서 목록과 추세를 제공한다.
- 행동: 날짜 선택 → S05. 복귀 시 필터·날짜를 보존하고 설정 변경을 목록과 추세에 반영한다.
- 지표: 지정 조건으로 기록을 골라 비교하고 조건 차이를 같은 조건의 변화로 해석하지 않은 테스트 수 ÷ 해당 비교 테스트 시도 수 × 100.
- 상태 제안: 조건에 맞는 기록 없음이면 현재 필터·검색 범위를 알리고 필터 해제 동작을 제공한다. 이는 전체 측정 기록이 없다는 뜻과 구분한다.

### S05 · 날짜별 체성분 기록

**목적:** 측정값과 측정 조건을 확인하고 추세 포함 여부를 저장한다.

- 진입: S04 날짜 선택. 복귀: S04.
- 표시: 선택한 측정일·원본 값·단위·측정 조건, 현재 포함 여부. 조건 설명은 진단·오류 확정 문구로 쓰지 않는다.
- 행동: 포함/제외 선택 → `체성분 기록 저장하기` → S04 반영 확인.
- 값 삭제와 추세 제외는 다르다. 이번 과업에 원본 삭제를 추가하지 않는다.
- 지표: 설정 저장·목록 및 추세 반영·원본 보존을 모두 확인한 테스트 수 ÷ 해당 설정 테스트 시도 수 × 100.
- 상태 제안: 저장 오류 시 선택을 보존하고 재시도를 제공한다. 저장 전 성공 표시를 하지 않는다. 10/22 측정 조건 차이 안내는 실제 증가·오류 단정 없이 제시한다.

### S06 · 지난 상담

**목적:** 주어진 조건에 맞는 상담을 찾는다.

- 진입: 주 메뉴 지난 상담 또는 관련 상담 바로가기. S07에서 복귀한다.
- 표시: 상담일시, 주제, 상담 상대, 결론 또는 내용 미리보기. AI/코치 출처와 원문/요약을 구분한다.
- 내부 기능: 날짜·상담 상대·주제 필터와 질문/답변/결론 검색.
- 행동: 상담 선택 → S07. 복귀 시 검색어·필터·스크롤을 유지한다.
- 부수 진입: `상담 내용 남기기` → A01. 부수 화면 미구현 시 이를 기능이 완성된 것처럼 표시하지 않는다.
- 지표: 주어진 주제·날짜·상담 상대 조건에 맞는 상세를 연 테스트 수 ÷ 해당 찾기 테스트 시도 수 × 100.
- 상태 제안: 최초 상담 없음과 검색 결과 없음은 별도 안내한다. 시연용 샘플 전환이 있다면 예시임을 표시한다.

### S07 · 상담 상세

**목적:** 상담 결론·당시 맥락·출처를 확인하고 오늘 계획에 연결한다.

- 진입: S06 또는 관련 상담 바로가기. 뒤로 가기 시 원래 진입 맥락으로 돌아간다.
- 표시: 상담일시·주제·상담 상대·질문·답변·선택적 결론, 원문/요약 여부, 연결된 계획.
- 결론 필드가 없으면 답변 원문을 확인하게 한다. AI가 추출한 요약은 원래 상담 결론인 것처럼 표시하지 않는다.
- 내부 기능: 오늘 운동 계획 선택·연결 저장·연결 확인. 날짜·계획 이름으로 대상을 구분한다.
- 한 상담은 선택적으로 계획 1개와 연결한다. 이미 다른 계획에 연결되어 있으면 기존 연결을 알리고 자동 재연결하지 않는다. 여러 계획 연결은 별도 검토 사항이다.
- 계획이 없거나 연결 저장 실패 시 완료로 표시하지 않는다. 다음 행동을 안내한다.
- 지표: 상담 내용·맥락·출처 확인과 올바른 계획 연결 저장·대상 확인을 모두 충족한 테스트 수 ÷ 해당 연결 테스트 시도 수 × 100.
- 연결로 계획의 수치나 운동 실행 상태를 바꾸지 않는다.

### A01 · 상담 내용 남기기 (부수 제안)

- 목적: 사용자가 가진 상담을 직접 저장한다. 필수 7개 화면의 기본 흐름에 강제하지 않는다.
- 표시·입력: 상담일시·주제·상담 상대·질문·답변, 선택적 결론. 원문과 요약을 구분한다.
- 행동: 저장 후 입력 내용·날짜·상담 상대가 정확히 저장되었는지 확인한다.
- 지표: 입력한 내용·날짜·상담 상대가 정확히 저장된 테스트 수 ÷ 해당 저장 테스트 시도 수 × 100.
- 상태 제안: 입력 오류·저장 실패 시 내용 보존과 오류 수정·재시도 경로를 제공한다.

## 8. 평가 기준

- 화면별 핵심지표는 3절의 1개로 유지한다. 성공 건수/시도 건수와 성공률을 함께 기록한다.
- 시도 0건·미실시는 미측정이다. 실패 0건과 혼동하지 않는다.
- 날짜·대상·요청 과업·성공 조건을 테스트 전에 정한다. 성공 조건은 위 화면별 설명을 따른다.
- AI 이해와 조건 해석은 관찰과 질문으로 확인한다. 클릭 이벤트만으로 이해했다고 간주하지 않는다.
- 실제 사용성 테스트·짝 리뷰는 아직 하지 않았다. 결과·목표 수치를 임의로 채우지 않는다.

## 9. 테마별 변경 범위와 통합

- 지킬 것: 7개 화면, 과업 순서·연결, 필수 행동, 이름·문구, 원본 데이터와 예시 구분, 사용자 선택, 측정 기준.
- 변경 가능: 영역 배치, 표·목록·카드·차트 등의 요소 유형, 여백·정보 밀도, 색·글꼴·강조. 필수 행동을 숨기거나 삭제하지 않는다.
- 세 테마는 동일한 기준 자료와 시연용 샘플에서 각각 시작한다. 다른 테마 결과물을 덮어쓰거나 디자인 원문 3개를 동시에 적용하지 않는다.

## 10. 구현 전 남은 결정

- 공통 배치안 2~3개를 비교하고 기준 배치·지킬 동작의 노출 위치를 결정한다.
- 과업 2·3의 상태 표현과 추가 상태 제안 채택 여부를 확인한다.
